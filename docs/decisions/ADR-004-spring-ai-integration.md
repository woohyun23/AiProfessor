# ADR-004: Spring AI 경계와 OpenAI 초기 제공자 채택

- 상태: 승인
- 결정일: 2026-11-04
- 적용 범위: 채팅·요약·문제 생성, 임베딩, Vector Store 연동
- 관련 ADR: ADR-003

## 배경

AiProfessor는 PDF 청크 임베딩, 검색 근거 기반 요약, 문제 생성과 주관식 평가를 위해 외부 AI 모델을 호출한다. 제공자별 SDK를 도메인 로직에서 직접 사용하면 모델 교체, 테스트, 사용량 기록과 장애 정책이 여러 모듈에 흩어진다.

Spring Boot 마이그레이션과 RAG·LLM 학습이 프로젝트 목표이므로 Spring 생태계 안에서 Chat Model, Embedding Model과 Vector Store를 일관된 방식으로 다룰 필요가 있다.

## 결정 기준

- LLM·임베딩 제공자의 SDK 타입이 도메인에 노출되지 않아야 한다.
- 프롬프트, 모델 버전, 토큰·지연·비용을 추적할 수 있어야 한다.
- 단위 테스트에서 외부 API 없이 응답과 실패를 재현할 수 있어야 한다.
- 특정 제공자 변경 시 비즈니스 로직 수정을 최소화해야 한다.
- 근거 청크와 인용 정보를 잃지 않아야 한다.

## 검토한 선택지

| 선택지 | 장점 | 단점 | 판단 |
|---|---|---|---|
| OpenAI SDK 직접 사용 | 제공자 기능에 빠르게 접근 | SDK 결합, 교체·테스트 경계 약화 | 제외 |
| Spring AI를 도메인 전체에서 직접 사용 | 초기 구현이 빠름 | Spring AI 타입이 도메인으로 전파될 수 있음 | 제외 |
| 내부 Port + Spring AI Adapter | 제공자·프레임워크 격리, 테스트 용이 | 변환 계층과 인터페이스 구현 필요 | 선택 |
| 직접 HTTP Client 구현 | 완전한 제어 | 스트리밍·오류·모델별 호환을 직접 유지 | 제외 |

## 결정

Spring AI를 AI 통합 어댑터로 사용하고 초기 LLM·임베딩 제공자는 OpenAI로 한다. 단, 도메인과 Application Service는 Spring AI 또는 OpenAI 타입에 직접 의존하지 않는다.

다음 내부 포트를 정의한다.

| 포트 | 책임 |
|---|---|
| `ChatGenerationPort` | 근거와 생성 설정을 받아 구조화된 생성 결과 반환 |
| `EmbeddingPort` | 텍스트 목록을 임베딩 벡터로 변환 |
| `VectorSearchPort` | 소유권·문서 조건과 Top-K로 관련 청크 검색 |

Spring AI Adapter가 `ChatModel`, `EmbeddingModel`, `VectorStore` 호출과 내부 DTO 변환을 담당한다. 다른 모듈은 제공자 모델명이나 SDK 응답 객체가 아니라 내부 계약만 사용한다.

### 공통 호출 정책

- 모든 프롬프트에 `promptVersion`을 부여한다.
- 생성 결과에 모델, 제공자, 근거 청크, 생성 시각을 기록한다.
- `ai_usages`에 입력·출력 토큰, 지연 시간과 추정 비용을 저장한다.
- 연결·응답 타임아웃을 설정하고 재시도 가능한 오류만 제한적으로 재시도한다.
- 구조화 출력은 역직렬화와 비즈니스 검증을 통과한 경우에만 저장한다.
- API 키는 환경 변수 또는 AWS 비밀 저장 방식으로 주입하고 로그·DB에 기록하지 않는다.
- 모델 장애가 발생해도 근거 없는 결과를 임의로 만들어 성공 처리하지 않는다.

### 아직 확정하지 않은 항목

다음 값은 모델 품질·비용 실험 후 별도 설정 및 문서에서 확정한다.

- Chat Model 이름과 생성 파라미터
- Embedding Model 이름과 벡터 차원
- 요청당·월간 비용 상한
- 입력 토큰과 PDF 페이지 제한 정책
- 로컬 개발용 대체 모델 또는 stub 범위
- 제공자 장애 시 자동 fallback 여부

MVP에서는 여러 제공자로 자동 fallback하지 않는다. 모델마다 출력 품질과 임베딩 공간이 달라 결과가 조용히 변할 수 있기 때문이다.

## 결과

### 긍정적 결과

- Spring Boot 설정·관측과 AI 호출을 일관되게 구성할 수 있다.
- 도메인은 제공자와 Spring AI의 변경 영향을 직접 받지 않는다.
- 테스트용 Adapter로 비용 없이 정상·시간 초과·형식 오류를 재현할 수 있다.

### 감수할 결과

- Spring AI가 지원하지 않는 제공자 고유 기능은 별도 Adapter 확장이 필요하다.
- 추상화가 모든 모델의 의미 차이를 제거하지는 못한다.
- 라이브러리 업그레이드 시 설정과 반환 형식에 대한 회귀 테스트가 필요하다.

## 검증 계획

- 고정 샘플 PDF와 골든 질문으로 검색·생성 품질을 분리해 평가한다.
- Chat·Embedding Adapter 계약 테스트와 외부 API 통합 테스트를 분리한다.
- 토큰, 비용, 지연 시간과 실패율이 `ai_usages`에 기록되는지 검증한다.
- 모델을 테스트 Adapter로 교체해도 Application Service가 변경되지 않는지 확인한다.

## 재검토 조건

- 필요한 제공자 기능을 Spring AI가 안정적으로 지원하지 못한다.
- 프레임워크 변환 비용이나 제약이 장애·성능의 주요 원인으로 측정된다.
- 사내·로컬 모델 운영으로 제공자 경계가 변경된다.
- 복수 제공자 fallback이 비용·가용성 요구사항으로 확정된다.
